# Stera Icons — agent guide

pnpm monorepo for `stera-icons`, a React icon library published to npm.

| Path | What it is |
|------|------------|
| `packages/icons` | The published `stera-icons` package (ESM-only, React peer dep) |
| `apps/docs` | Private Next.js site deployed to [stera.sh](https://stera.sh). Has its own [AGENTS.md](apps/docs/AGENTS.md) |

Human contributor docs live in [CONTRIBUTING.md](CONTRIBUTING.md). Read it before adding or changing icons.

## Commands

Use **pnpm** only (never npm or yarn). Node >= 22; `.nvmrc` pins 24. Run from the repo root.

| Command | What it does |
|---------|--------------|
| `pnpm install` | Install dependencies |
| `pnpm build` | Full build of `stera-icons` (tsup + icons + declarations) |
| `pnpm build:icons` | Regenerate icon components, metadata and declarations only |
| `pnpm --filter stera-icons exec vitest run` | Run tests once. `pnpm test` starts watch mode in a terminal |
| `pnpm lint` | ESLint on `packages/icons/src` |
| `pnpm dev:docs` | Run the docs site. Requires `pnpm build` first |

Do not run a whole-project `tsc` in `packages/icons`: it runs out of memory on the generated icon files. `pnpm build` is the type check.

## Source vs. generated files

Never hand-edit a generated file. Change the source or the generator, then rebuild.

| File | Kind | In git |
|------|------|--------|
| `packages/icons/icons-export.json` | **Source.** Figma export; the only source of icon artwork, names and tags | yes |
| `packages/icons/src/{IconBase,DynamicIcon}.tsx`, `src/{base,dynamic,types,utils}.ts`, `src/__tests__/` | **Source** | yes |
| `packages/icons/scripts/` | **Source.** The build pipeline | yes |
| `packages/icons/src/icons/*.tsx` | Generated | yes |
| `packages/icons/src/{index,dynamic-variants,dynamicIconImports}.ts` | Generated | yes |
| `packages/icons/dist/icons.meta.json` | Generated. Holds per-icon version history; **must be committed** | yes |
| Rest of `packages/icons/dist/` | Generated | no |
| `apps/docs/data/` | Generated by `apps/docs/scripts/generate-icons.mjs` | no |

Things to know about the build:

- `icons-export.json` is about 10 MB. Never read it whole; query it with `node -e` or `jq`.
- `build-icons.js` deletes and regenerates `src/icons/` on every run, and rewrites the `exports` field of `packages/icons/package.json`.
- The `.d.ts` files in `dist/esm` are written from templates in `scripts/generate-declarations.js`, not emitted from source. If you change a public type in `src/`, update the matching template.
- After a build, `git status` should show only files you meant to change.

## Adding or changing icons

Order matters. The changeset must exist before the build, because the build reads it to stamp `versionAdded` on new icons.

1. `pnpm changeset`
2. `node packages/icons/scripts/hash-versioning.js info` — confirm `Has pending changesets: true`
3. Update `packages/icons/icons-export.json`
4. `pnpm build:icons`
5. Commit everything, including the generated `src/` files and `packages/icons/dist/icons.meta.json`

## Versioning and release

| Bump | When |
|------|------|
| `patch` | Bug fixes, small refinements to existing icons |
| `minor` | New icons, new backwards-compatible features |
| `major` | Icon removals or renames, and any other breaking change |

- Any change that affects what ships to npm (`src/`, `scripts/`, `README.md`, `llms.txt` in `packages/icons`) needs a changeset. Changes to `apps/docs` do not.
- Releases are automated by `.github/workflows/release.yml`. **Never run `pnpm changeset version`, `pnpm version-packages`, `pnpm release` or `npm publish`.**

## Docs that must stay in sync

When the public API, icon count, requirements or behavior of `stera-icons` changes, update all of:

- `packages/icons/llms.txt` — LLM usage guide. Ships to npm and is served at `stera.sh/llms.txt`
- `packages/icons/README.md` — ships to npm
- `apps/docs/components/docs-content.tsx` — the docs page on stera.sh
- `README.md` — icon count in the stats table

## Conventions

- Conventional commits: `feat:`, `fix:`, `chore:`, `docs:`.
- Do not add AI attribution or `Co-Authored-By` trailers to commits or pull requests.
- To render icons in an app or gallery, use the `stera-icons/dynamic-variants` components with `dist/icons.meta.json`, as `apps/docs/scripts/generate-icons.mjs` does. Do not render from the raw SVG strings in `icons-export.json`.
